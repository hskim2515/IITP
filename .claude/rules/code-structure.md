# 코드 구조 규칙

판단 기준은 길이가 아니라 **책임**이다. 잘 분리된 파일이 길어질 수도 있는 것은 정상이며,
길다는 이유만으로 나누면 책임은 그대로인 채 파일 수만 늘어난다.

## 적용 범위

- **새로 작성하거나 크게 손대는 코드**에 적용한다.
- 기존 파일이 이 규칙에 맞지 않더라도 **요청 없이 리팩터링하지 않는다.**
  작업 중 눈에 띄면 한 줄로 지적만 하고, 분리 여부는 사용자가 판단한다.
- 제외: 생성 코드(`iitp-rest/src/main/generated/`), 빌드 산출물.
- CLAUDE.md의 파일명 계약(`{PascalKey}DataSourceLayer.ts`, `{PascalKey}FeatureLayer.ts`
  자동 등록 등)이 우선한다. 규칙과 충돌하면 계약을 따르고 그 사실을 언급한다.

## 한 문장 원칙

파일/클래스가 하는 일을 **한 문장으로 설명할 수 있어야 한다.**
새 파일을 만들기 전에 그 한 문장을 먼저 적고, 클래스 주석으로 남긴다.

"~하고, ~한다"로 이어지는 것 자체는 문제가 아니다("파싱하고 검증한다"는 하나의 책임이다).
이어붙인 것들이 **서로 다른 이유로 바뀌는지**를 본다 — 그렇다면 그 자리가 분리 지점이다.

## 단계와 계층

**한 클래스가 여러 단계를 거치는 것은 정상이다.**
순차 단계로 이루어진 알고리즘을 단계별 클래스로 쪼개면 하나의 흐름이 여러
파일로 흩어지기만 하고 결합은 그대로 남는다 — 공유 상태가 지역변수에서
컨텍스트 객체 필드로 옮겨갈 뿐이다.

문제는 단계의 개수가 아니라, 단계들이 **서로 다른 계층**에 속하는 경우다.

- 외부 I/O(DB·파일·네트워크) · 좌표계 변환 · 도메인 규칙 판정 · 출력 직렬화
  — 이들이 한 클래스 안에서 차례로 등장하면 계층이 섞인 것이다.
- 반면 같은 계층 안의 여러 단계(탐색 → 병합 → 검증)는 그 자체로 하나의
  알고리즘이며 분리 대상이 아니다.

## 중복 판단

중복 자체는 문제가 아니다. **잘못된 추상화가 중복보다 비싸다** —
독립적으로 진화할 두 코드를 억지로 묶으면 이후 모든 변경이 양쪽 조건 분기로 오염된다.

기준은 "두 곳이 **같은 이유로** 바뀌어야 하는가"이다.

- **다른 이유로 바뀐다** (I/O 전략, 실행 환경, 성능 제약, 적용 정책)
  → 중복을 유지한다. 코드 모양이 같아도 우연이며, 곧 갈라진다.
- **같은 이유로 바뀐다** (실측으로 튜닝된 임계값, 크래시 회피 로직, 도메인 규칙)
  → 한 곳에 둔다. 이건 코드 중복이 아니라 **지식 중복**이고, 갈라지면 버그가 된다.

## 의도적 중복의 기록

중복을 남기기로 했다면 **양쪽에 서로를 참조하는 주석**을 남긴다.

한쪽에만 있는 기능을 발견했을 때 그것이 의도적 차이인지 전파 누락인지
코드만 보고 판단할 수 있어야 한다. 이 구분이 안 되는 순간부터
두 파일은 각자 다른 방향으로 조용히 갈라진다.

```java
// 축퇴 shape 방지 — KtdbNetworkConverter.buildPassthroughConnections와 동일 원인·동일 수정
```

## 기존 파일에 추가할 때

추가하려는 코드가 **그 파일의 한 문장 설명에 포함되는지** 먼저 확인한다.
포함되지 않으면 파일이 비어 보이더라도 새 파일로 만든다.

"관련은 있으니까 여기 두자"가 반복되면서 파일이 무너진다.
설명 문장을 늘려야 코드가 들어맞는 상황이면, 늘리지 말고 분리한다.

## 미사용 코드

호출부 없는 private 헬퍼를 "나중에 쓸지도 모르니" 만들지 않는다.
이번 작업에서 새로 생겼는데 쓰이지 않게 된 코드는 작업 완료 전에 제거한다.

단, **호출부가 안 보인다고 기존 코드를 지우지 않는다.** JAXB(`@XmlElement`),
Jackson, Spring(`@EventListener`, `@Scheduled`), 리플렉션은 정적 호출부 없이
런타임에 호출한다. 확신이 없으면 지우지 말고 언급만 한다.

## 매직넘버의 근거

임계값·계수가 실측·시행착오에서 나온 값이면 **그 근거를 상수 바로 옆에 남긴다.**
재현 조건, 관측된 증상, 실패했던 대안까지 적는다 — 근거를 코드보다 짧게 요약한다.

`docs/` 로 빼는 것은 **여러 파일이 함께 참조해야 하는 설계 지식**뿐이다.
한 상수에만 해당하는 경위는 코드 옆에 둔다.

주석 분량은 분리 신호가 아니다. 근거 주석이 쌓여 파일이 무거워졌다면
문제는 주석이 아니라 한 파일이 지고 있는 책임의 수다.
